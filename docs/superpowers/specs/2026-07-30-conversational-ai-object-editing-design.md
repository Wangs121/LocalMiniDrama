# 对象级 AI 对话修改设计

## 背景

当前角色、场景、道具提取以及各类提示词生成都是一次性 AI 操作。识别错误后，创作者需要理解多个字段之间的关系并手工同步修改；提示词不符合创作意图时，也只能直接编辑或重新随机生成，无法用“再年轻一点”“保留服装，只调整发型”这类自然语言连续修正。

本设计为已存在的角色、场景、道具和分镜增加对象级 AI 对话修改能力。识别遗漏仍由创作者使用现有入口手工添加对象；对象保存并获得 ID 后，与自动识别出的对象共用同一套对话修补逻辑。

## 目标

- 创作者可以围绕单个角色、场景、道具或分镜进行多轮对话。
- AI 能结合当前对象、当前集剧本、项目风格和相关分镜理解修改要求。
- 未应用的候选草稿可以继续通过下一轮对话迭代。
- AI 只生成完整候选对象；字段变更列表和文本差异由本地代码确定性计算。
- 创作者可以逐字段审阅并选择性应用，应用只进入表单，现有保存按钮仍是业务数据写入边界。
- 对话历史按对象永久保存在本地 SQLite 数据库中，可继续或清空。
- 修改视觉内容后保留已有媒体，并明确标记媒体可能过期；不自动产生新的生成费用。

## 非目标

- AI 不自动新增、删除、合并角色、场景、道具或分镜。
- 不提供跨对象批量修改或全局项目助手。
- 不自动重新生成图片或视频。
- 不提供已保存业务数据的一键回滚。
- 不把聊天记录作为业务对象的真实数据源；业务表仍是唯一事实来源。
- 不改变现有提取、单次提示词生成和手工编辑能力。

## 用户流程

### 修正已存在对象

1. 创作者打开角色、场景、道具或分镜编辑器。
2. 编辑器加载该对象的历史对话。
3. 创作者输入自然语言要求，例如“年龄改成 28 岁，保留黑色风衣，把提示词里的金发改成黑色短发”。
4. 后端读取上下文并请求 AI 生成完整候选对象。
5. 后端校验候选对象，并与本轮请求中的当前表单快照进行本地字段比较。
6. 前端展示逐字段旧值、新值及长文本差异高亮。
7. 创作者可以继续对话迭代候选草稿，也可以勾选字段并应用到表单。
8. 创作者点击现有保存按钮后，表单内容才写入业务表。

### 补充识别遗漏对象

1. 创作者使用现有“添加角色”“添加场景”或“添加道具”入口创建最小对象。
2. 对象按现有流程保存并获得 ID。
3. 创作者重新打开对象编辑器，使用与自动识别对象相同的 AI 修改面板补全字段和提示词。

第一版不为未保存对象创建临时会话。这避免临时 ID、孤立历史和取消新增后的清理问题。

## 范围与字段适配器

后端使用统一的对象修改服务，并为每种对象提供独立适配器。适配器定义可编辑字段、字段类型、长度限制、枚举、上下文查询和媒体过期规则。任何未列入白名单的字段都不会发送给 AI，也不会出现在候选对象中。

### 角色

第一版可编辑字段：

- `name`
- `role`
- `appearance`
- `personality`
- `description`
- `voice_style`
- `polished_prompt`
- `negative_prompt`
- `stages`

`identity_anchors` 继续由现有专用“提炼视觉锚点”操作维护，不由通用对话直接改写。媒体 URL、本地路径、参考图路径、Seedance 素材信息、排序、状态和时间戳均为只读。

### 场景

第一版可编辑字段：

- `location`

- `prompt`
- `polished_prompt_single`
- `polished_prompt`
- `negative_prompt`

其中 `prompt` 是当前业务表中的场景描述字段。实现前须将现有业务代码已使用的 `polished_prompt_single` 补入迁移 SQL 和 `ensureColumns()`，保证新旧数据库都具备该列。

### 道具

第一版可编辑字段：

- `name`
- `type`
- `description`
- `prompt`
- `negative_prompt`

### 分镜

- `movement`
- `lighting_style`

- `character_ids`

`character_ids` 和 `prop_ids` 是适配器提供的规范化数组字段，分别映射现有分镜关联表；`scene_id` 映射分镜场景关联。AI 只能选择同一项目内的有效对象 ID。

## 上下文构建

每轮请求以前端提交的当前表单快照为基准，确保 AI 能看到尚未保存的手工修改。后端补充以下上下文：

- 当前对象所有可编辑字段。
- 上一轮尚未应用的候选对象。
- 当前集剧本。
- 项目内容类型、视觉风格、叙事风格和画幅等相关设置。
- 与当前对象关联的分镜摘要。
- 最近若干轮用户要求和助手结果摘要。
- 同项目内可引用的角色、场景、道具 ID 与名称，仅在处理分镜关系字段时提供。

角色可能跨集复用。请求必须携带当前编辑上下文中的 `episode_id`；若未提供，则优先使用对象现有关联集，再使用项目中最新编辑的集。场景和道具优先使用自身 `episode_id`。分镜使用自身所属集，并补充相邻分镜以维持连续性。

完整历史永久保存并可查看，但不会无限加入模型上下文。超过预算时按以下优先级保留：

1. 当前用户要求。
2. 当前表单快照。
3. 当前候选对象。
4. 当前集剧本中与对象相关的片段。
5. 相关及相邻分镜。
6. 最近对话。

较早聊天记录仅从模型输入中截断，不从数据库删除。由于当前候选对象包含前序迭代的累计结果，截断旧消息不会丢失当前工作草稿。

剧本和其他创作内容作为不可信数据放入明确分隔的上下文区，系统提示词要求模型不得执行其中出现的指令。

## AI 输出合同

AI 不负责声明旧值、字段变更列表或应用范围。它只返回版本化的完整候选对象：

```json
{
  "schema_version": 1,
  "candidate": {
    "name": "林夏",
    "role": "main",
    "appearance": "28 岁，黑色短发……",
    "personality": "冷静、克制",
    "description": "……",
    "voice_style": "……",
    "polished_prompt": "……",
    "negative_prompt": "……",
    "stages": []
  },
  "note": "保留了黑色风衣，仅调整年龄与发型。"
}
```

候选对象必须包含该对象类型的全部可编辑字段。空值使用 `null`、空字符串或空数组，具体形式由字段适配器统一规范化。`stages`、`character_ids` 和 `prop_ids` 等结构化字段在 AI 合同中使用数组，适配器负责与现有表单或数据库中的 JSON 文本互转。`note` 可选，只用于对话展示，不参与数据写入或差异判断。

调用时优先使用现有 `aiClient.generateText()` 的 JSON 模式。若提供方明确不支持 `response_format`，服务降级为严格 JSON 提示并使用现有安全 JSON 解析器。内容首次解析或 Schema 校验失败时，允许一次格式修复请求；仍失败则本轮失败，不创建候选建议。

禁止用缺失字段默默覆盖现有值。候选缺少任一必需键、包含未知键、类型错误、无效枚举、跨项目关联或超长文本时，整份候选拒绝，不做部分接纳。

## 本地差异计算

后端对当前表单和候选对象分别执行相同的规范化，再按适配器字段顺序比较。差异结果由本地代码生成：

```json
{
  "base_snapshot_hash": "...",
  "changes": [
    {
      "field": "appearance",
      "old_value": "22 岁，金色长发……",
      "new_value": "28 岁，黑色短发……"
    }
  ]
}
```

后端不接受 AI 提供的旧值或变更说明。前端对字符串字段执行本地文字差异算法；中文按字符和标点分词，较长英文片段按词比较。数组和枚举使用结构化值比较并以名称展示。

请求发出时记录规范化表单摘要。响应返回后，若当前表单摘要已变化，前端将结果标记为过期，不允许直接应用，并提供基于最新表单重新生成的操作。

## 连续迭代与选择性应用

- 第一轮候选以当前表单为基础。
- 存在未应用候选时，下一轮以该候选为工作草稿继续修改。
- 新候选与当前表单重新比较，因此差异卡始终表示“如果现在应用，会改变哪些表单字段”。
- 新候选生成后，上一候选标记为 `superseded`，但仍保留在历史中。
- 用户勾选字段并点击“应用所选”后，只有所选字段写入前端表单。
- 未选字段标记为未采用，不会隐式进入下一轮工作草稿。
- 应用后继续对话时，以更新后的当前表单为基础。
- “应用”不调用角色、场景、道具或分镜更新接口。
- 点击现有保存按钮后，业务表才更新。

建议状态用于历史展示，可取 `pending`、`superseded`、`applied_to_form`、`partially_applied_to_form`、`discarded`。业务对象本身始终是最终事实来源。若对话状态更新失败，不得阻止正常保存业务对象。

## 数据库设计

新增 `ai_edit_conversations`：

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `entity_type TEXT NOT NULL`
- `entity_id INTEGER NOT NULL`
- `drama_id INTEGER NOT NULL`
- `episode_id INTEGER`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- `UNIQUE(entity_type, entity_id)`

新增 `ai_edit_messages`：

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `conversation_id INTEGER NOT NULL`
- `reply_to_message_id INTEGER`
- `client_request_id TEXT`
- `role TEXT NOT NULL`
- `content TEXT NOT NULL`
- `base_snapshot_hash TEXT`
- `candidate_json TEXT`
- `diff_json TEXT`
- `proposal_status TEXT`
- `selected_fields_json TEXT`
- `request_status TEXT NOT NULL`
- `error_code TEXT`
- `created_at TEXT NOT NULL`

`entity_type` 只允许 `character`、`scene`、`prop`、`storyboard`。`role` 只允许 `user`、`assistant`，`request_status` 只允许 `pending`、`completed`、`failed`。候选与差异仅存在于成功的助手消息中。助手消息通过 `reply_to_message_id` 关联触发它的用户消息；同一会话内的 `client_request_id` 唯一，用于避免超时重试产生重复轮次。

每个对象默认只有一条会话。清空操作在事务中删除该会话的消息并更新时间，不删除业务对象。对象被软删除后，普通会话接口返回不存在；历史数据保留，以便对象恢复后继续访问。

### 媒体过期状态

新增以下布尔列，默认值均为 `0`：

- `characters.image_stale`
- `scenes.image_stale`
- `props.image_stale`
- `storyboards.image_stale`
- `storyboards.video_stale`

字段适配器维护“字段 -> 受影响媒体”映射。共享媒体新鲜度服务负责实际设置和清除标记，现有手工保存、单次提示词生成和新对话保存路径都调用该服务，避免不同入口行为不一致。相关字段发生实际变化且对象已有对应媒体时，将标记设为 `1`。成功生成或替换对应媒体后清零。失败、取消或只应用到未保存表单时不改变持久化标记。

参考图、图片 URL、视频 URL 和生成任务字段不允许由对话候选直接修改。

## API 设计

统一路由前缀：

```text
GET    /api/v1/ai-edits/:entity_type/:entity_id
POST   /api/v1/ai-edits/:entity_type/:entity_id/messages
PATCH  /api/v1/ai-edits/:entity_type/:entity_id/proposals/:message_id
DELETE /api/v1/ai-edits/:entity_type/:entity_id/messages
```

`GET` 返回会话、消息和当前可恢复的最新建议。首次访问时可惰性创建会话。

`POST messages` 请求体：

```json
{
  "message": "保留服装，把年龄改为 28 岁",
  "client_request_id": "4a719aef-...",
  "episode_id": 12,
  "current_snapshot": {},
  "previous_candidate_message_id": 98,
  "base_snapshot_hash": "..."
}
```

响应包含助手展示文本、候选消息 ID、经校验的候选对象、本地差异和原样返回的表单摘要。用户消息以 `request_status = pending` 先持久化，再执行 AI 调用；成功后在一个短事务中保存助手候选消息并把用户消息标记为 `completed`。调用失败时保留用户消息，在短事务中将其标记为 `failed`，并保存一个不含候选对象的失败助手结果，方便历史界面显示和重试。网络调用期间不持有 SQLite 事务。

`PATCH proposals` 只更新建议展示状态和所选字段，不更新业务表。请求必须验证消息属于当前对象会话。

`DELETE messages` 清空单个对象的对话历史，需要前端二次确认。

## 前端设计

实现可复用的对象对话组件和通用组合式函数，四类编辑器只负责提供表单字段映射。

### 角色、场景和道具

现有编辑弹窗在桌面端扩展为左右布局：左侧保留表单和媒体，右侧显示 `AI 修改` 对话区。弹窗使用视口约束，避免固定百分比宽度在小屏溢出。

窄屏使用“对象信息 / AI 修改”两个页签。页签切换不销毁表单或聊天状态。

### 分镜

传统创建页和画布模式都在现有分镜编辑区域增加 `AI 修改` 操作。点击后打开同一个分镜对话编辑器；两处复用相同组件、接口和字段适配器，不维护两套聊天状态。

分镜编辑器左侧按“内容与关联 / 镜头与画面 / 提示词”组织完整分镜字段，右侧复用对象对话区。角色、场景、道具关系只允许选择当前项目中的有效对象。保存仍通过现有分镜更新接口一次性写入，不自动重建或覆盖创作者确认后的图片、视频提示词。

分镜列表和画布同时展示持久化的图片、视频过期状态；状态只用于提醒创作者重新生成，不自动触发媒体任务。两处保存后都重新加载项目数据，以接口返回值作为最终状态。

### 对话区

- 消息历史使用独立滚动区域。用户消息正文正常显示；助手消息默认只显示时间、状态和“查看 AI 回复”操作，完整原文默认折叠，创作者按需展开或收起。
- 底部提供多行输入和发送图标按钮。
- 请求进行中禁用重复发送，并允许关闭弹窗；关闭时取消前端等待，后端结果仍可在下次打开时加载。
- 当前成功建议的主展示区只保留本地计算的字段差异，不重复显示助手正文。完整助手回复只能从对应历史消息的“查看 AI 回复”入口展开。
- 每个变化字段提供复选框、字段标签、旧值和新值；长文本显示增删高亮。
- 操作区提供“应用所选”和“放弃建议”。
- 清空历史位于更多菜单中，并要求二次确认。
- 历史建议明确显示已应用到表单、部分应用、已放弃或已被后续建议替代。

角色和场景当前未完整展示的 `personality`、`voice_style`、`negative_prompt`、`polished_prompt_single` 等已纳入字段，需要在表单中提供可审阅的对应控件，不能让 AI 修改不可见字段。

## 未保存修改

打开编辑器时保存一份规范化初始表单快照。以下任一变化都视为未保存：

- 创作者手工编辑字段。
- 应用 AI 建议。
- 上传、移除或替换参考图。

关闭存在未保存修改的编辑器时，提供保存、放弃、继续编辑三个选择。放弃后恢复业务表数据；已经保存的聊天历史仍保留，但未应用或未保存的候选不会被当作当前业务值。

## 异常处理

- 未配置文本模型：返回现有 AI 配置指引，不创建候选建议。
- 对象不存在或已软删除：返回 404，不创建会话。
- 当前集不存在或不属于项目：返回 400。
- AI 提供方超时或请求失败：保留用户输入和现有候选，允许重试。
- JSON 模式不兼容：降级到严格 JSON 文本模式。
- JSON 解析或 Schema 校验失败：自动修复一次；仍失败则不生成建议。
- 候选与当前表单没有差异：保存助手消息并显示“未发现需要应用的字段”。
- 关联 ID 无效或跨项目：拒绝整份候选，并记录不含敏感上下文的诊断日志。
- 响应返回前表单发生变化：前端阻止应用过期建议。
- 对话状态记录失败：不阻止表单保存，但提示历史状态未同步。
- 媒体重新生成失败：保持过期标记为 `1`。

日志不得记录完整剧本、完整候选对象、API 密钥或用户消息正文。只记录对象类型、对象 ID、会话/消息 ID、模型、耗时、响应长度和错误类别。

## 测试策略

### 后端单元测试

- 四类字段适配器的白名单、默认值、类型、枚举和长度校验。
- 完整候选对象缺键、未知键、错误类型、无效关联和超长文本的拒绝行为。
- JSON 模式、不支持 JSON 模式时的兼容降级，以及一次格式修复。
- 当前表单与候选对象的确定性字段差异。
- 角色、场景、道具、分镜的上下文范围和项目隔离。
- 上一候选连续迭代、部分应用后的重新基线和候选替代状态。
- 会话创建、历史读取、清空和软删除对象访问。
- AI 失败或校验失败不会更新业务表。
- 相关字段变化设置图片/视频过期标记。
- 图片或视频生成成功清除对应标记，失败时保留。
- `polished_prompt_single` 在新数据库和升级数据库中均存在。

### 前端单元测试

- 表单规范化和摘要计算。
- 字段差异展示与中文长文本差异高亮。
- 全选、部分选择、放弃和继续迭代。
- 表单在请求期间变化时拦截过期响应。
- AI 建议只改前端表单，不自动调用保存接口。
- 未保存关闭确认的三种结果。
- 媒体过期状态和重新生成入口。
- 角色、场景、道具和两个分镜入口复用同一组件。
- 桌面双栏与窄屏页签的响应式约束。

- 运行后端全部测试：`cd backend-node && node --test test/*.test.js`。
- 运行前端全部测试：`cd frontweb && node --test test/*.test.js`。
- 构建前端：`cd frontweb && npm run build`。
- 启动后端与 Vite 开发服务器，在桌面和移动视口验证四类对象的完整流程。
- 验证未配置 AI 时应用其余功能仍可正常使用。

## 验收标准

- 自动识别对象和人工新增后保存的对象能使用同一 AI 修改入口。
- 同一对象关闭并重新打开后能看到完整历史并继续对话。
- “再年轻一点”“保留上一版服装”等指令会基于上一候选继续迭代。
- AI 不提供旧值或变更列表；页面展示的差异完全由本地代码生成。
- 用户能逐字段选择并应用，未选择字段不会进入表单或后续候选。
- 未点击保存时，业务表内容保持不变。
- AI 返回无效 JSON、越权字段或跨项目关联时，业务数据和表单均不变化。
- 影响视觉内容的已保存修改会保留已有媒体并显示过期状态。
- 重新生成成功后，相应媒体过期状态消失。
- AI 无权新增、删除、合并或跨对象修改业务数据。
